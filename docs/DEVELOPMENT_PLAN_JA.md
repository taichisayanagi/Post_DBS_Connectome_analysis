# 開発・論文への組み込み方針

## 目的

新しい患者の術後CTとT1／T2および拡散MRIから，電極アーチファクトの除外範囲を検査し，native-space構造コネクトームとgradientの縦断変化を再現可能に定量する研究用ソフトウェアを作る．臨床診断，刺激設定の推薦，MRI撮像安全性の判定には使用しない．

## 実装の順序

0. 実行環境：利用者のPCにあるFSL，MRtrix3，FreeSurfer，NextBrain，Python，MATLAB，SPM12および実際の解析経路で必要となるその他のツールを利用する．本体に一括同梱せず，大容量コンテナも必須にしない．実行パス・バージョン・追加資源・ライセンス設定を工程別に確認する環境チェックを実装し，既存環境を無断で変更しない．詳細は[依存関係の方針](LOCAL_DEPENDENCIES.md)を参照．
1. 正本の凍結と移植：現行論文の設定，入力の種類，マスク履歴，ラベル順序を記録する．今回の493ノードはコホート固有の凍結基盤であり，他の患者に自動適用しない．
2. 入力管理：DICOMシリーズの一覧化と人によるCT／T1／T2／DWI／逆位相画像の選択．b値，bvec数，撮像方向，撮像日，磁場強度，重複スキャンを確認する．患者名を解析キーにしない．
3. 位置合わせ：CT→解剖MRI→DWIの変換を型付きで追跡する．RAS／LPS，変換順序と逆変換，qform／sformの競合を検査する．T1とT2は単純な互換入力にせず，別の承認済み経路を定義する．
4. 電極マスク：CT由来の位置を起点にDWI信号欠損の追跡を移植する．全シャフトの被覆と飛び地をQCし，人が修正・承認する．術後同士は解剖学的登録後の和集合マスクを用い，適用範囲の変動を記録する．単なる同一affineを登録済みと解釈しない．
5. 構造コネクトーム：DWIの撮像条件に応じて前処理とFODモデルを選ぶ．surface SchaeferとNextBrain，ACT，streamline生成，マスク交差streamline除外，SIFT2再推定，node割当と行列化を実装する．モデル／アトラス資源はライセンス確認後に別途取得する．
6. Gradient：左右別，明示されたlog変換と閾値，10成分計算／4成分保持，共通またはLOSO参照を用途ごとに固定する．時点差では同じ参照と同じnodeを必須にする．G1–G4に運動・認知という機能名を自動付与しない．
7. 出力：マスクQC，除外率，行列QC，gradient，eccentricity，dispersion，parcel displacement，設定・版・入出力ハッシュを保存する．全解析を専用の日時付きフォルダに分離する．
8. 独立検証と正式release：開発版はGitHub公開済み．既存研究との数値一致，別症例・別プロトコールのDICOMからの完走，失敗例の検出，第三者の既存ツール環境での再現を確認してから，検証済みreleaseのバージョン固定と永続識別子取得を行う．

## 初期実装の境界

現在のv0.1.0.dev0はローカルのブラウザGUIとCLIの初期実装であり，DICOM変換と準備済み入力からの下流処理を対象とする．GUIからの入力選択，ジョブ実行，工程・状態・経過時間・ログの表示，マスクQCを実装した．CTからの自動位置検出，信号欠損追跡，前処理・アトラス生成は未実装．centerlineからの管状マスクは候補生成用であり，研究で最終採用したマスクアルゴリズムと同一とは主張しない．

## 科学的な貢献の位置づけ

貢献は，既存の画像処理アルゴリズムを発明し直すことではなく，術後画像の電極アーチファクトを明示的に扱い，その除外・登録・解析の履歴とQCを一体化して，他施設が検証できる形にすることにある．既存ツールより優れるという主張には別途比較実験が必要である．コード公開は小標本，撮像条件差，臨床評価の不足，選択後の相関推定といった論文の限界を解消しない．

## 論文への追加予定

- Methods：実装の入出力，依存ソフトウェア，承認ゲート，処理履歴，エラー時の停止条件．
- Results：既存パイプラインとの数値一致，別DICOMでの処理成功・失敗，手動修正頻度，実行時間・メモリ．検証前に数値を記載しない．
- Discussion：研究方法の再利用と外部再現の促進．臨床バイオマーカー確立とは区別する．
- Code availability：実際の公開URL，release tag，commit hash，ライセンス，取得後の永続識別子．公開前に入手可能と記載しない．
- Supplementary：合成データのチュートリアル，処理仕様，QC基準，バージョン互換性と検証表．

Movement Disorders版Markdownには開発版の公開URLと未検証範囲を記載済み．正式なソフトウェア検証のMethods／Resultsへの採用は，全経路検証が完了するまで保留する．
